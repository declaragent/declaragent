## North star

Declaragent is "production ready" when a multi-host enterprise fleet can be authored, deployed, monitored, and trusted under genuinely **untrusted** input. Concretely: every headless runtime (`up`, `fleet run`, `run`) enforces the declared tool set behind a real permission gate (no Bash/Write/Edit or undeclared MCP/plugin leaks, no host secrets in Bash subprocesses); cross-host RPC fails **closed** on unknown/unsigned senders, every delegation is signed on both request and response legs, and hop/deadline/cycle brakes bound runaway delegation; a declared Kafka/NATS/SQS/AMQP/MQTT fleet actually round-trips a sync delegation through the shipped CLI with enterprise auth, idempotent receive, reconnect-with-backoff, and truthful health; the control plane is safe to expose; a rendered Kubernetes manifest boots a Ready pod that stays up with full config and persistent state; no inbound→dispatch→outbound hop silently loses work, under a written delivery-semantics contract; multi-tenancy, a dollar spend cap, verifiable audit retention, and cross-host GDPR erasure are enforced, not dormant; one distributed trace spans RPC hops with LLM golden signals so "agent stopped responding" is diagnosed in under 10 minutes; and CI is a real gate — branch-protected, fail-closed release sentinel, integration lanes that actually execute, a real soak streak, and generated doc/claims cross-checks so the five-pillar scoreboard cannot drift from code.

## Definition of Production Ready (acceptance gates)

All of the following must be true, each proven by a test, not self-reported:

1. **Untrusted-input safety** — an agent declaring `tools.defaults` exposes exactly those (plus auto-exempt capability tools) in `up`/`fleet run`/`run`; a grep finds no headless `mode:'bypass'` gate; Bash never spawns with host secret env; per-principal channel permissions enforced.
2. **Trustworthy cross-host RPC** — a forged envelope from an unregistered/unsigned peer is rejected on the live fleet-run path when strict; `rpc.auth.enabled:true` implies strict per-agent; every built-in delegation (request and response) is signed; deadline enforced; hop-limit + cycle brake terminate an A→B→A loop with bounded `provider.complete` count.
3. **Real broker round-trip** — `fleet run` completes a sync `RequestAgent` round-trip across two processes over each declarable broker with no warn-skip, transport-aware respond + caller reply binding, and at-most-once handler execution on redelivery.
4. **Enterprise transport/channel parity** — every channel auto-reconnects with backoff and reports truthful health; every transport accepts SASL_SSL/TLS/mTLS/IAM from git-versioned config via secret refs; AMQP reconnects and awaits publisher confirms; a cited parity matrix is the auditable artifact.
5. **Safe control-plane exposure** — `bindAddress` consumed; remote bind without auth refuses to start; Host-header forgery rejected; read + mutation routes authed by default; auth rejections audited to SIEM; `/status` reports real per-agent counters and breaker state; a documented end-to-end TLS+bearer remote topology is proven by test.
6. **Real deployment** — a CI kind-smoke gate is green: rendered k8s/helm/kustomize over the fleet-starter reaches `condition=Available`; the container runs **foreground** `up` serving `/healthz`+`/readyz`+`/metrics` on the pod IP; full agent dir + persistent SQLite state present; one `fleet deploy` adapter applies + rollout-checks + rolls back; the default image is a published, buildable ref.
7. **No silent work loss** — `dlq requeue`/`events replay` actually re-execute and report the true outcome; a SIGKILL mid-turn recovers exactly once; `down`/Ctrl+C drains in-flight turns; outbound channel sends are durably retried with a channel-send DLQ; `DELIVERY_SEMANTICS.md` enumerates each hop's guarantee.
8. **Real observability** — with an OTLP endpoint set, one trace spans Slack-inbound → engine `llm.turn` → RPC hop across two hosts; LLM golden signals (latency/errors/tokens/cost) on `/metrics`; Kafka consumer lag is end-committed and scrapeable; a daemon heartbeat makes `DaemonHeartbeatTimeout` pageable; "agent stopped responding" root-caused in <10 minutes.
9. **Enterprise governance** — `tenants.yaml` is loaded and enforced (ingress, active-session, tool-call, dollar-spend quotas fail-closed with a `quota_exceeded` audit); `audit prune` keeps `audit verify` green via per-tenant chain partitioning + serialized sink writes; `erase --subject` removes a subject across audit/events/sessions/memory cross-host with `--dry-run`; per-subject memory isolation works.
10. **CI is an enforced gate** — `main` is branch-protected with required checks; the release sentinel keys on the release branch and fails closed; the always-on webhook→provider→channel→audit hermetic E2E is required; dark transport/SIEM lanes execute >0 tests; a machine-computed soak streak gates releases.
11. **Config + claims integrity** — a typo in any security-relevant `agent.yaml` sub-block fails validation; `agent validate` + schema-checking `fleet validate` ship; every decorative knob is wired or removed; generated cross-checks block drift in cookbook YAML, runbook verbs, alert metrics, and the scoreboard; status docs match code with file:line evidence.
12. **Coordinated 0.8.0 zero-trust cutover** — `rpc.auth` default true + `allowLoopback` false + strict `agent.yaml` + tools default flip ship as **one** migration with preview/warn windows, inspectors, changesets, and a passing rolling-upgrade rehearsal.

## Workstreams (design detail)

### WS1 · Enforce tool permissions in every headless runtime + scrub Bash env — *3.5–4.5 wk* (top security blocker)
- **Current:** headless runtimes hand every agent the full builtin set (incl. unremovable Bash/Write/Edit/Agent) plus all MCP+plugin tools behind a `mode:'bypass'` gate (`up-cli.ts:1433-1439`, `fleet-run-llm-handler.ts:202-205`); `tools.defaults` is parsed (`load-agent.ts:766`) but never filters; no `permissions:` schema key; Bash spawns `/bin/sh -c` inheriting the daemon's whole `process.env` (no scrub).
- **Changes:** add a `permissions:` schema block compiled to a real `GateConfig`; tool-list resolver that filters to `tools.defaults`, globs MCP names, and **fails boot on unknown** [breaking]; wire filtered tools + real gate into `up`, `fleet run`, and `run` [breaking]; `defaultGateFor(loaded)` safe default; scrub Bash subprocess env (denylist + `PATH/HOME/LANG/TMPDIR/USER` keep-set + allowlist override); per-turn gate override to enable per-principal channel permissions; wire the dormant `resolveForChannel`.
- **Tests:** declared `[Read,Glob,Grep]` exposes exactly those (not bypass); unknown tool name fails boot; headless Bash attempt returns EPERM and never spawns; `printenv` through Bash does not leak `*_API_KEY`/`*_SECRET`/`*_TOKEN`; a spawn-shape pin test so `THREAT_MODEL.md` and code cannot diverge.
- **Deps:** WS2 (who-may-invoke complements what-tools-may-run); channel adapters must populate `event.meta.principal` (verify Telegram/Discord/WhatsApp parsers).

### WS2 · RPC auth fail-closed + envelope signer + 0.8.0 readiness — *3–4 wk*
- **Current:** verify registry **fails open** — an envelope from a sender absent from `rpc-peers.yaml` is accepted on both inbound paths (`agent-inbox.ts:305-317`, `fleet-run.ts:640-642`); no producer ever signs (`request-agent.ts:268` hard-codes `auth:{kind:'internal'}`, `RpcAuthProvider.sign()` is dead code); only asymmetric OIDC/OAuth2 providers exist (need external IdP).
- **Changes:** add an HMAC peer-auth variant (zero-infra default) reusing core crypto; make verify fail-**closed** in strict mode on both inbound paths; thread a sign registry into `RequestAgent` and sign every outbound envelope (request and response legs); wire sign+strict-verify into `fleet-run` and `up` boot with a flip pre-flight [breaking]; extend `fleet audit-rpc` to check the **sign** side.
- **Tests:** forged `from: agent://not-in-registry` rejected on both paths; tampering any signed field fails verification (round-trip over memory + a networked stub); with the flip on + HMAC both sides, built-in delegation succeeds (the scenario broken today); with the flip on + peers declared + no signer, boot aborts with an actionable error.
- **Deps:** WS4 — must land jointly on `fleet-run.ts` `onRequest`/boot to avoid a fail-open window; one coordinated envelope strict-schema bump (auth + hops + deadline).

### WS3 · Control-plane auth hardening — *3–4 wk*
- **Current:** listener hard-binds `127.0.0.1` (`up-cli.ts:757`), so cross-host verbs need a hand-built proxy; default `allowLoopback:true` + a scalar-path Host check that ignores the plumbed `peerIp` (`control-plane-auth.ts:383-388,470-480`) lets any caller sending `Host: 127.0.0.1` bypass bearer auth; `/status` serves hard-coded zeros that `fleet ps` renders as healthy.
- **Changes:** consumed `bindAddress` knob + pure resolver; fail-closed refusal on non-loopback bind without auth; default `allowLoopback:false` when auth configured + consume `peerIp` [breaking]; require auth/scoping on read routes; plumb real `/status` counters (dispatched/rejected/breaker-open + channel readiness); document + test the secure remote topology (loopback bind + `trustedProxies` + XFF + bearer through a TLS-terminating proxy).
- **Deps:** owes WS6 a probe-compatible auth path; converges with the `rpc.auth` flip into one 0.8.0 migration.

### WS4 · Wire broker transports into `fleet run` + per-envelope respond + receive idempotency + RequestAgent in `up` — *4–5 wk* (the hub)
- **Current:** `fleet run` calls `startFleetDaemon` with **no** `transportFactories` (`fleet-run.ts:1252-1264`); `FleetRunDeps` has no field for them, so `externalFactories` is `{}` and every non-memory transport is warn-skipped (`fleet-run.ts:394-397`); the responder hard-pins `respondTransport = transports.get('memory')` (`fleet-run.ts:584-591`) and stamps `replyTo=memory://`, so a Kafka request on host B is answered on B's local memory bus host A can never observe.
- **Changes:** a config→transport factory-builder module (the missing adapter layer); thread `transportFactories` from declared capabilities into `fleetRun`; select respond transport **per-envelope** from the inbound `replyTo` scheme; make caller-side reply binding transport-aware; consumer-side idempotency keyed on `messageId` (reuse extracted core `IdempotencyCache`); give `up` a `RequestAgent` tool + inbound capability serving over a broker; reconcile outbound auth with the WS2 signer; re-point the soak harness at the real verb.
- **Tests:** two-process Kafka sync round-trip (no warn-skip); a regression test for the memory respond hard-pin that fails pre-change; redelivered `messageId` runs the handler at-most-once with a metric; agents without `rpc-peers.yaml` have byte-identical tool sets.

## Top execution risks

1. **Two designs are unsound as written (WS6, WS8).** Building them verbatim ships broken or wastes cycles. → Treat the reviewer corrections (above) as **gating design sign-off** before any PR starts.
2. **Breaking-change blast radius — four 0.8.0 flips** (tools default, `rpc.auth` strict, `allowLoopback`, strict `agent.yaml` that throws on boot) can take down running fleets on a routine upgrade. → Ship every flip in warn/dry-run/preview behind escape hatches for ≥1 minor, auto-exempt capability tools, converge into one documented migration with inspectors + changesets, and require a passing mixed-version rolling-upgrade rehearsal.
3. **WS4 is the single hub** — if it slips it cascades to WS2/WS7/WS9-soak/WS11 and the soak can't start. → Highest-priority serial item, dedicated owner, land first with a stub `signOutbound` hook + two-memory-bus CI stand-ins so dependents build immediately.
4. **The soak is calendar-bound (~7 weeks)** — even bug-free code can't be declared ready until a streak accrues; a naive "7-week streak" gate incentivizes rubber-stamp overrides. → Start the real soak in Phase 2; gate on "most-recent scheduled soak green + nightly ≥7" with API retry/backoff and an audited break-glass override.
5. **Systemic effort underestimation** — every reviewer raised estimates; bundled workstreams hide multi-package migrations. → Plan against the corrected numbers; split WS8 (4 sub-WS) and WS5 (outbox); budget review + changeset + docs + migration time explicitly.
6. **Silently regressing a just-fixed property** (capability-tool filter breaking working agents; fail-closed quotas causing a self-inflicted outage; truthful channel health flapping k8s probes and evicting pods; Phase-1 dedup turning a recoverable retry into a guaranteed timeout). → Require back-compat byte-identical + explicit failure-path tests as exit criteria; ship enforcement in dry-run/log-only with breach counters first; add a k8s readiness grace window for reconnecting channels; include the sync response-replay cache in Phase 1.
7. **CI-gate footguns** — branch protection needs an admin token the Actions `GITHUB_TOKEN` lacks and can deadlock a solo maintainer; required transitive checks can block unrelated merges on a new CVE. → Bootstrap protection out-of-band; add CODEOWNERS/bot-approval for self-authored PRs; verify the sentinel on a throwaway release PR before `enforce_admins`; add a quarantine/allowlist policy for flaky or CVE-driven required checks.
